## 1. 游戏策划

### 1.1 游戏背景

**游戏名称**：斗牛（DOU NIU / Bull Fight）

**游戏主题**：斗牛是一种广泛流行于中国南方地区的传统扑克牌游戏，又称“牛牛”、“斗牛”。游戏以扑克牌点数组合论输赢，节奏明快、规则简单，深受各年龄层玩家喜爱。本作品以 SFML 图形库为引擎，将传统的面对面斗牛玩法移植到 PC 平台，实现人机对战模式。

**玩法来源**：传统中国民间扑克玩法——“斗牛”。

**目标玩家群体**：
- 喜爱棋牌类休闲游戏的玩家
- 对传统扑克文化感兴趣的玩家
- 希望在 PC 端进行单机人机对战的用户

**核心体验**：玩家与 3 名 AI 对手一桌对战，通过叫庄、抢庄、组牌、比牌四个阶段决出胜负，体验斗牛独有的心理博弈与运气乐趣。

### 1.2 游戏规则

#### 1.2.1 基本设定

- **参与人数**：4 人（1 真人 + 3 AI）
- **使用牌数**：一副标准 52 张扑克牌（去掉大小王）
- **每人牌数**：5 张
- **游戏局数**：不限，玩家可随时退出，资金为零则游戏结束

#### 1.2.2 点数计算

在斗牛中，扑克牌的点数按以下规则计算：

| 牌面 | 点数 |
|:---:|:---:|
| A | 1 点 |
| 2 ~ 9 | 对应面值（2~9 点） |
| 10、J、Q、K | 10 点 |

#### 1.2.3 牌型等级（由低到高）

本游戏实现了完整的斗牛牌型判定体系，共 14 个等级：

| 等级 | 名称 | 判定条件 | 赔付倍数 |
|:---:|:---|:---|:---:|
| 0 | 没牛 | 任意 3 张之和均非 10 的倍数 | 1× |
| 1~6 | 牛1 ~ 牛6 | 3 张和为 10 倍数，余 2 张之和个位为 1~6 | 1× |
| 7~9 | 牛7 ~ 牛9 | 3 张和为 10 倍数，余 2 张之和个位为 7~9 | 2× |
| 10 | 牛牛 | 3 张和为 10 倍数，余 2 张之和也是 10 倍数 | 3× |
| 11 | 五花牛 | 5 张全为 J/Q/K | 4× |
| 12 | 炸弹 | 4 张点数相同 | 4× |
| 13 | 五小牛 | 5 张均 < 5 且总和 ≤ 10 | 5× |

#### 1.2.4 游戏流程

每局游戏分为五个阶段：

**阶段一：下底注**
- 每局开始，所有玩家自动扣除底注（默认 100 筹码）进入底池。

**阶段二：发牌（前 4 张）**
- 系统向每位玩家发 4 张牌，作为叫庄/抢庄的判断依据。

**阶段三：叫庄 & 抢庄**
- 随机决定叫庄顺序。
- 每位玩家依次选择：**叫庄**（成为庄家候选人）、**抢庄**（在已有人叫庄后抢夺庄位）、或**过牌**（放弃）。
- 每次抢庄，赔率翻倍（×2 → ×4 → ×8...，困难模式初始即 ×16）。
- 若原叫庄者被抢，享有一次**反抢回合**（Counter-Rob），体现传统斗牛中的“守庄权”。
- 若无人叫庄，则随机分配庄家。

**阶段四：发第 5 张牌 & 组牌**
- 叫庄结束后，所有玩家获得第 5 张牌。
- 玩家进入**组牌阶段**：从 5 张手牌中选择 3 张作为“凑牛组合”，系统自动计算剩余 2 张的“牛数”。
- AI 玩家自动完成最优组牌。

**阶段五：比牌 & 结算**
- 庄家与其他每位闲家逐一比较牌型等级。
- 牌型等级高者获胜，赢得：`底注 × 赔率 × 牌型赔付倍数`。
- 困难模式下底注为基础 100，简单模式赢输金额 ×4 但单局上限 1000。
- 若人类玩家资金为负，涉及该玩家的结算赔率 ×2（负债惩罚机制）。

#### 1.2.5 胜负判定

- 每局结束后按牌型等级分胜负，资金实时结算。
- **游戏结束条件**：玩家资金归零或主动退出。

### 1.3 特色与创新

对比传统斗牛游戏，本作品在以下方面进行了改进与创新：

1. **完整的三阶段叫庄机制**  
   实现了“叫庄 → 抢庄 → 反抢”的完整流程，而非简化为随机庄家。AI 每一轮都有独立的叫/抢/过决策，让叫庄阶段成为真正的心理博弈。

2. **难度分层的 AI 策略**  
   提供简单（EASY）、普通（NORMAL）、困难（HARD）三个难度级别，AI 的抢庄概率、手牌评估阈值、赔率策略均有所不同。困难模式下赔率直接 ×16 起步，AI 更加激进，极大提升了游戏挑战性。

3. **玩家自主组牌**  
   与传统自动比牌不同，本作允许玩家手动选择 3 张牌进行组牌，增加了策略深度——有时需要权衡“保牛”还是“冲高牛”。

4. **图像化 UI 与动画**  
   使用真实扑克牌 PNG 图片渲染手牌，配合发牌动画（卡牌逐张飞入）、结算动画，以及各类牌型贴图（牛0~牛牛、五花牛等），极大提升了视觉体验。

5. **存档与每日奖励**  
   通过 `MoneySave` 系统实现玩家金币持久化存储，支持每日登录奖励机制，增加了游戏的持续吸引力。

6. **负债惩罚机制**  
   当人类玩家金币为负时，涉及该玩家的赔率翻倍——这一设计既增加了风险管理的策略性，也模拟了真实赌局的“债台高筑”压力。

#### 2.3.2 规则处理

**叫庄/抢庄/反抢机制**（`GameLogic::startBiddingPhase` / `playerCallBanker` / `playerRobBanker` / `advanceBidder`）：

```
随机排列叫庄顺序 → 轮流选择：
  ├── 无人叫庄 → 叫庄（赔率×2，困难×16）/ 过牌
  ├── 有人叫庄 → 抢庄（赔率翻倍）/ 过牌
  └── 一轮结束 → 若原叫庄者被抢 → 反抢回合
```

**牌型评估算法**（`GameLogic::evaluateHandQuality`）：
1. 优先检查特殊牌型：五小牛 → 炸弹 → 五花牛
2. 遍历所有 3 张组合（C(5,3) = 10 种），找和能被 10 整除的
3. 有牛的取余数（0→牛牛，1~9→牛1~牛9），无牛返回 0

**组牌阶段**（`startCardArrangementPhase` / `evaluatePlayerArrangement`）：
- 玩家从 5 张手中点选 3 张，系统实时计算这 3 张能否凑牛及最终牛数
- 确认后提交，AI 自动遍历所有 3 张组合选择最优解

**结算算法**（`GameLogic::settleRound`）：
```
for 每位闲家 vs 庄家：
    winner = (闲家牌型 > 庄家牌型) ? 闲家 : 庄家
    payMultiplier = getPayMultiplier(winner牌型)
    effectiveOdds = 赔率 × (玩家负债 ? 2 : 1)
    change = 100 × effectiveOdds × payMultiplier
    if 简单难度: change ×= 4, 单局上限 1000
```

#### 2.3.3 计算机对手（AI）

AI 系统是本项目的亮点，按难度分三层策略：

**4 张牌手牌强度评估**（`evaluate4CardStrength`，0~100 分）：
- 已有 3 张凑成 10 倍数：直接返回 70~79（几乎必抢）
- 花牌（J/Q/K）数量加权：+13/张
- 最佳 2 张取模距离加权
- 对子奖励 +7，A 灵活性 +3

**AI 叫庄/抢庄策略**（`processAIBid`）：

| 难度 | 叫庄阈值 | 抢庄策略 |
|:---|:---|:---|
| EASY | 强度 ≥ 55 | 强度差距 ≥ 12 且赔率 ≤ ×4，概率 15%~40% |
| NORMAL | 强度 ≥ 38 | 强度差距 ≥ 3 且赔率 ≤ ×8，概率 35%~75% |
| HARD | 强度 ≥ 25（位置靠后 ≥ 18） | 强度差距 ≥ -8 且赔率 ≤ ×16，概率 60%~92%，位置优先时几乎必抢 |

**AI 组牌**（`aiAutoArrange`）：暴力遍历全部 10 种 3 张组合，选择牛数最大的方案。

### 2.4 关键代码解析

#### 2.4.1 斗牛牌型评估算法（核心）

```cpp
int GameLogic::evaluateHandQuality(const Player &player) const
{
    const auto cards = player.getAllCards();
    if (cards.size() != 5) return BULL_NONE;

    int vals[5], ranks[5], total = 0;
    for (int i = 0; i < 5; i++) {
        vals[i] = cards[i].getValue(); // J/Q/K→10, A→1
        ranks[i] = static_cast<int>(cards[i].getRank());
        total += vals[i];
    }

    // 五小牛：5张都<5 且总和≤10
    bool allSmall = true;
    for (int i = 0; i < 5; i++)
        if (vals[i] >= 5) { allSmall = false; break; }
    if (allSmall && total <= 10) return FIVE_SMALL;

    // 炸弹：4张相同rank
    for (int i = 0; i < 5; i++) {
        int cnt = 0;
        for (int j = 0; j < 5; j++)
            if (ranks[j] == ranks[i]) cnt++;
        if (cnt >= 4) return BOMB;
    }

    // 五花牛：全J/Q/K
    bool allFace = true;
    for (int i = 0; i < 5; i++) {
        int r = ranks[i];
        if (r != JACK && r != QUEEN && r != KING)
            { allFace = false; break; }
    }
    if (allFace) return FIVE_FLOWER;

    // 有牛/没牛：找任意3张和为10的倍数
    for (int i = 0; i < 5; i++)
        for (int j = i + 1; j < 5; j++)
            for (int k = j + 1; k < 5; k++) {
                int sum3 = vals[i] + vals[j] + vals[k];
                if (sum3 % 10 == 0) {
                    int remain = (total - sum3) % 10;
                    return (remain == 0) ? BULL_BULL : remain;
                }
            }
    return BULL_NONE;
}
```

**设计说明**：采用“优先级排除法”——先检特殊牌型，再三重循环枚举 10 种 3 张组合。时间复杂度 O(1)（固定 5 张牌），算法清晰且易于扩展新牌型。

#### 2.4.2 AI 叫庄/抢庄决策

```cpp
void GameLogic::processAIBid()
{
    int bidder = getCurrentBidderIndex();
    int myStrength = evaluate4CardStrength(players[bidder]);

    if (!hasSomeoneCalledBanker()) {
        // 叫庄：根据难度不同，阈值从55→38→25递减
        bool shouldCall = false;
        switch (aiDifficulty) {
            case AI_EASY:  shouldCall = (myStrength >= 55); break;
            case AI_NORMAL: shouldCall = (myStrength >= 38); break;
            case AI_HARD:  shouldCall = (myStrength >= 25)
                         || (bidderOrder >= 2 && myStrength >= 18); break;
        }
        if (shouldCall) playerCallBanker(bidder);
    } else {
        // 抢庄：比较与当前庄家的强度差，计算抢庄概率
        int gap = myStrength - evaluate4CardStrength(players[lastCallerIndex]);
        int robChance = 0;
        // 根据难度、强度差距、位置顺序、赔率等级动态计算概率
        // ...（详细逻辑见 GameLogic.cpp）
        if (robChance > 0 && (rand() % 100) < robChance)
            playerRobBanker(bidder);
        else
            advanceBidder();
    }
}
```

**设计说明**：AI 决策模拟真人心理——“手强则叫，位优则抢”；简单 AI 趋于保守（只有好牌才动），困难 AI 利用位置优势和概率搏杀，赔率控制防止无限加注。

#### 2.4.3 主循环事件分发

```cpp
void GameLoop::handleEvents()
{
    while (auto event = window.pollEvent()) {
        if (event->is<sf::Event::Closed>()) window.close();
        else if (event->is<sf::Event::MouseButtonPressed>()) {
            auto mousePos = window.mapPixelToCoords(sf::Mouse::getPosition(window));
            if (currentState == START_SCREEN) {
                // 开始界面：START / QUIT
            } else if (currentState == GAME_PLAYING) {
                if (isArrangementPhase)  → handleArrangementClick();
                else if (isSettlePhase)  → handleSettleClick();
                else if (isBiddingPhase) → handleBiddingClick();
            }
        }
        else if (event->is<sf::Event::KeyPressed>()) {
            if (Space && isBidding) → playerCallBanker / playerRobBanker;
            if (Space && isSettle)  → startNewRound();
            if (Escape)             → return to menu;
        }
    }
}
```

**设计说明**：按游戏状态（开始界面 / 叫庄中 / 组牌中 / 结算中）划分事件处理路径，避免条件混乱。键盘（Space/Esc）和鼠标双通道输入，提升操作便利性。

```cpp
}
```

**设计说明**：每张牌通过花色英文名 + 点数字符串拼接成 key（如 `SpadeA`），存入 `unordered_map<string, Texture>`。绘制时通过 `getCardTextureKey()` 快速查找对应纹理，O(1) 访问，52 张纹理在加载阶段一次性初始化。

## 4. 结论与总结

### 4.1 开发过程中遇到的问题及解决方案

| 序号 | 问题描述 | 解决方案 |
|:---:|:---|:---|
| 1 | **SFML 3 与 SFML 2 的 API 差异**：SFML 3 中大量 API 改为 `Vector2` 和 `sf::Event` 使用 `union` → `std::optional`，早期代码兼容报错 | 全面适配 SFML 3 API：使用 `sf::Vector2f(x, y)` 替代 `sf::Vector2f(x, y)`、`event->is<T>()` 替代 `event.type`、`sf::Mouse::getPosition(window)` 替代 `sf::Mouse::getPosition()` |
| 2 | **卡牌 PNG 资源路径问题**：Windows 下 VS Code 工作目录与 exe 运行目录不一致，导致纹理加载失败 | 使用绝对路径 + 相对路径双重回退策略，加载失败时输出日志，确保两种场景均可用 |
| 3 | **AI 叫庄死循环**：早期实现中所有 AI 同时决策，导致一帧内走完全部叫庄流程 | 引入 `AI_BID_INTERVAL = 1.2s` 逐帧驱动机制，使用 `sf::Clock` 计时器让 AI 逐个轮流出价，实现自然节奏 |
| 4 | **反抢（Counter-Rob）机制设计**：传统斗牛中，原叫庄者被抢后有“守庄权”，用简单的顺序轮转难以实现 | 引入 `robBackPhase` 标志位，一轮抢庄结束后检测原叫庄者是否被抢，若是则单独调度原叫庄者进入反抢回合 |
| 5 | **组牌阶段 UI 交互**：需要实现“点击选中 3 张牌 → 确认 → 提交”的流程，且选中数量需限制 | 使用 `arrangementSelectedIndices` 向量追踪选中状态，最多 3 张；选中/取消选中即时反映在卡片位置偏移和边框高亮上 |
| 6 | **按钮图片透明区域**：`Button2.png` 图片有大面积透明边缘，直接用整图渲染导致按钮间距异常 | 通过像素扫描算法自动检测非透明像素包围盒（Bounding Box），生成 `buttonCropRect`，渲染时裁剪透明区域 |
| 7 | **随机名字重复**：AI 玩家从名字池中随机取名，偶尔出现重名 | 使用 Fisher-Yates 打乱 + 去重检查，从 34 个人名池中确保每次选出的 3 个 AI 名字互不重复 |
