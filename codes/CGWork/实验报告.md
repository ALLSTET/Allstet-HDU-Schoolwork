# 实验报告

## 实验名称：基于光线追踪的Cornell Box场景渲染

---

## 1. 具体内容

本实验要求实现一个完整的光线追踪渲染器，能够渲染经典的Cornell Box场景。具体任务包括：

- 实现光线与球体、三角形的相交检测算法
- 实现直接光照计算（包括阴影检测）
- 实现镜面反射效果
- 实现间接光照（颜色渗透效果）
- 实现HDR色调映射和Gamma校正
- 构建Cornell Box场景（包含红色左墙、绿色右墙、白色后墙/地板/天花板）
- 在场景中放置一个蓝色反射球体和一个白色立方体
- 在天花板上设置区域光源
- 使用SDL2库实时显示渲染结果

---

## 2. 设计思路

### 2.1 算法流程

```
开始
  ↓
初始化场景（Cornell Box + 物体 + 光源）
  ↓
对每个像素：
  ├─ 计算从相机发出的光线方向
  ├─ 调用trace()函数追踪光线
  │   ├─ 检测光线与所有物体的相交
  │   ├─ 找到最近的交点
  │   ├─ 计算环境光贡献
  │   ├─ 对每个光源：
  │   │   ├─ 计算阴影光线
  │   │   ├─ 检测是否被遮挡
  │   │   └─ 计算直接光照贡献
  │   ├─ 如果材质有反射率：
  │   │   └─ 递归追踪反射光线
  │   ├─ 如果深度<1：
  │   │   └─ 采样间接光照（颜色渗透）
  │   └─ 返回HDR颜色
  ├─ 应用色调映射（Reinhard + Gamma校正）
  └─ 存储到帧缓冲区
  ↓
使用SDL2显示渲染结果
  ↓
结束
```

### 2.2 关键技术点

**（1）光线-物体相交检测**
- **球体相交**：使用几何方法计算光线与球体的交点
- **三角形相交**：使用Möller-Trumbore算法，高效且数值稳定

**（2）光照模型**
- **环境光**：基础环境光项，避免完全黑暗区域
- **直接光照**：Lambertian漫反射模型，考虑光源衰减和阴影
- **镜面反射**：使用反射率参数混合漫反射和镜面反射
- **间接光照**：简化的半球采样，模拟颜色渗透效果

**（3）阴影检测**
- 从交点向光源发射阴影光线
- 检测阴影光线是否被其他物体遮挡
- 使用bias避免自相交问题

**（4）色调映射**
- **Reinhard色调映射**：`color / (color + 1)`，防止过曝
- **Gamma校正**：将线性空间转换为sRGB空间
- **关键**：只在最终输出时应用一次，不在递归过程中应用

## 3. 主要函数及其简要说明

### 3.1 数据结构

**`Vec3f`类**
- 三维向量类，支持向量运算（加减乘除、点积、叉积、归一化等）

**`Triangle`结构体**
- 存储三角形顶点、法线、材质属性（颜色、发射、反射率）
- `intersect()`: Möller-Trumbore算法实现光线-三角形相交检测

**`Sphere`类**
- 存储球心、半径、材质属性
- `intersect()`: 几何方法实现光线-球体相交检测

### 3.2 核心函数

**`Vec3f reflect(const Vec3f &raydir, const Vec3f &normal)`**
- 计算反射光线方向
- 公式：`reflectDir = raydir - 2 * dot(raydir, normal) * normal`

**`Vec3f toneMap(const Vec3f &hdrColor, float exposure, float gamma)`**
- 色调映射函数
- 应用曝光度 → Reinhard映射 → Gamma校正 → 颜色钳制
- 将HDR颜色转换为LDR颜色用于显示

**`Vec3f trace(const Vec3f &rayorig, const Vec3f &raydir, ...)`**
- 光线追踪主函数（递归）
- 参数：光线起点、方向、场景对象、递归深度
- 流程：
  1. 检测与所有物体的相交，找到最近交点
  2. 计算交点处的法线和材质属性
  3. 累加环境光贡献
  4. 对每个光源计算直接光照（含阴影检测）
  5. 如果材质有反射率，递归追踪反射光线
  6. 如果深度<1，采样间接光照
  7. 返回HDR颜色值

**`int main()`**
- 主函数
- 构建Cornell Box场景（墙壁、地板、天花板、光源）
- 添加场景物体（球体、立方体）
- 设置相机参数和投影
- 逐像素渲染，调用trace()和toneMap()
- 使用SDL2显示结果

## 4. 遇到的主要问题及解决思路

### 问题1：色调映射位置错误导致颜色异常

**问题描述**：
- 最初将色调映射放在`trace()`函数内部
- 导致每次递归调用时，中间结果也被映射
- 反射和间接光照计算使用了错误的颜色值
- 最终渲染结果出现颜色失真、过曝或颜色丢失

**解决思路**：
- 将色调映射从`trace()`函数中移除
- 创建独立的`toneMap()`函数
- 只在主渲染循环中对最终输出应用一次色调映射
- 确保`trace()`函数始终返回HDR颜色值，保持颜色计算的正确性

**关键代码修改**：
```cpp
// 错误做法（在trace内部）：
Vec3f trace(...) {
    // ... 计算color ...
    return toneMap(color);  // ❌ 错误！
}

// 正确做法（在main中）：
Vec3f hdrColor = trace(...);  // 返回HDR
Vec3f color = toneMap(hdrColor);  // ✅ 只映射一次
```

### 问题2：Vec3f缺少向量除向量操作

**问题描述**：
- Reinhard色调映射需要计算 `color / (color + 1)`
- `Vec3f`类只有标量除法，没有向量分量除法
- 编译错误：`no match for 'operator/'`

**解决思路**：
- 实现组件级别的除法操作
- 手动计算每个分量的比值

**代码修改**：
```cpp
// 修改前（错误）：
Vec3f mappedColor = color / (color + Vec3f(1.0f));  // ❌

// 修改后（正确）：
Vec3f mappedColor(
    color.x / (color.x + 1.0f),
    color.y / (color.y + 1.0f),
    color.z / (color.z + 1.0f)
);  // ✅
```

### 问题3：光照强度过高导致过曝

**问题描述**：
- 光源衰减系数设置过大（60和80）
- 光源发射强度过高（0.8）
- 导致场景过亮，细节丢失

**解决思路**：
- 降低光源衰减系数（球体光源：60→20，三角形光源：80→25）
- 适当降低光源发射强度（0.8→0.5，可根据需要调整）
- 增加环境光权重（0.1→0.2），提高基础亮度

### 问题4：间接光照权重过高

**问题描述**：
- 间接光照权重设置为0.20，导致颜色渗透过强
- 场景颜色变得不自然

**解决思路**：
- 降低间接光照权重至0.10
- 保持颜色渗透效果的同时避免过度影响

### 问题5：缺少limits头文件

**问题描述**：
- 使用`std::numeric_limits<float>::max()`但未包含`<limits>`头文件
- 编译错误

**解决思路**：
- 添加`#include <limits>`头文件

### 5.3 问题说明

**为什么会出现颜色异常问题？**

色调映射在递归过程中被错误应用是根本原因。光线追踪是一个递归过程：
- 主光线 → 反射光线 → 间接光照采样
- 如果每次递归都应用色调映射，会将HDR值压缩为LDR值
- 后续计算（如反射混合、间接光照累加）使用的是错误的LDR值
- 导致颜色计算链式错误，最终结果失真

**解决方案的正确性**：

通过在最终输出时只应用一次色调映射：
- `trace()`函数始终返回线性HDR颜色值
- 所有光照计算在HDR空间进行，保持数值精度
- 只在最后一步转换为LDR用于显示
- 确保了整个颜色计算流程的正确性
